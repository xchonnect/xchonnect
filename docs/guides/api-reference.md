# API references

Hosted API documentation exists only for the two crates published on crates.io, from
0.1.0-rc.2 on: [docs.rs/xchonnect-core](https://docs.rs/xchonnect-core) and
[docs.rs/xchonnect-wallet-kit](https://docs.rs/xchonnect-wallet-kit). Every other
reference, and the reference for any unreleased commit, is generated from the source in
this repository with the commands below. All of them are run from the repository root
(unless noted) and were verified on the current tree.

| Surface | Package | Generate with | Output |
|---|---|---|---|
| Rust crates | `xchonnect-core`, `-relay`, `-gateway`, `-wallet-kit`, `-conformance`, `-wasm`, `-uniffi` | `cargo doc --workspace --no-deps --locked` | `target/doc/<crate>/index.html` |
| TypeScript dApp SDK | `@xchonnect/dapp` | `npx typedoc@0.28 --out target/typedoc --tsconfig tsconfig.json src/index.ts` (in `sdk-ts/`) | `target/typedoc/index.html` |
| TypeScript declarations | `@xchonnect/dapp` | `npm run build -w @xchonnect/dapp` | `sdk-ts/dist/src/*.d.ts` |
| Swift (iOS wallets) | `Xchonnect` | `./scripts/build-swift.sh` | `target/swift/Sources/Xchonnect/Xchonnect.swift` |
| Kotlin (Android wallets) | `xchonnect.uniffi` | `./scripts/build-kotlin.sh` | `target/kotlin/src/main/kotlin/xchonnect/uniffi/xchonnect.kt` |

## Rust

```sh
cargo doc --workspace --no-deps --locked
open target/doc/xchonnect_core/index.html
```

Start at `xchonnect_core`: it carries the protocol types (envelopes, pairing, sessions) and
every crate's module docs state which spec section they implement. `--no-deps` keeps the
output to this workspace; drop it if you want the dependency docs too. Add `--open` to open
the browser directly.

`xchonnect-wallet-kit` currently emits two rustdoc warnings about ambiguous intra-doc
links; they do not affect the generated pages.

## TypeScript

The SDK source is fully annotated with TSDoc, so the generated reference is complete.
TypeDoc is not a project dependency — run it through `npx` so nothing is added to the
lockfile:

```sh
cd sdk-ts
npx typedoc@0.28 --out ../target/typedoc --tsconfig tsconfig.json src/index.ts
```

It reports a few warnings for types referenced but not exported from `src/index.ts`
(`InitInput`, `PowSolver`, `DappPairing`, the internal `Listener`); the documented public
surface is unaffected.

The declaration files produced by the normal build are the other authoritative reference:

```sh
./scripts/build-wasm.sh                 # needs wasm-bindgen-cli 0.2.129 (pinned)
npm ci --ignore-scripts
npm run build -w @xchonnect/dapp        # -> sdk-ts/dist/src/*.d.ts
```

The entry point [`sdk-ts/src/index.ts`](../../sdk-ts/src/index.ts) is the shortest
inventory of the public API: `XchonnectClient`, `Pairing`, `RelayClient`,
`OhttpTransport`, the session stores, the error types, the CHIP-0002 adapter and the
multi-party helpers.

## Swift and Kotlin

The Swift and Kotlin interfaces are **generated by UniFFI** from
[`bindings/uniffi`](../../bindings/uniffi), so the generated source file *is* the API
reference — it lists every function, class, record and error case with its exact types:

```sh
./scripts/build-swift.sh     # target/swift/Sources/Xchonnect/Xchonnect.swift (+ XCFramework)
./scripts/build-kotlin.sh    # target/kotlin/src/main/kotlin/xchonnect/uniffi/xchonnect.kt
```

Both scripts generate the bindings from a host build of the crate, so you get the sources
even without the platform toolchain: `build-swift.sh` skips the XCFramework when
`xcodebuild` is unavailable, and `build-kotlin.sh` skips the `.so` libraries without the
Android NDK and `cargo-ndk`. Neither script needs the other platform.

Read them together with [`bindings/uniffi/README.md`](../../bindings/uniffi/README.md),
which is the hand-written reference: boundary conventions (base64url strings, `now` passed
in, JSON text for CHIP-0002 payloads), the full exported API grouped by purpose, and
worked Swift and Kotlin pairing, relay, push and signing examples. Those samples are
compiled against the generated API in CI (`./scripts/test-swift.sh`).

For a narrative walkthrough rather than a symbol list, use the
[wallet integration guide](../wallet-integration.md).

## WASM core

[`bindings/wasm/README.md`](../../bindings/wasm/README.md) documents the browser-facing
conventions of the WASM core: base64url values, which secrets cross the boundary and why,
JSON-text decoded messages, the OHTTP types, and the Content-Security-Policy a signing
page needs (`script-src 'wasm-unsafe-eval'`, no `unsafe-eval`).

## Protocol-level references

The generated API docs describe *this* implementation. For anything another
implementation must match, use the normative documents:

| What | Where |
|---|---|
| Protocol specification | [`docs/spec/xchonnect-spec.md`](../spec/xchonnect-spec.md) |
| Relay HTTP API, error model, limits | [`docs/spec/wire/relay-api.md`](../spec/wire/relay-api.md) |
| CBOR structures (CDDL) | [`docs/spec/wire/envelope.cddl`](../spec/wire/envelope.cddl) |
| Pairing URI grammar and signature input | [`docs/spec/wire/pairing-uri.md`](../spec/wire/pairing-uri.md) |
| `/.well-known/xchonnect.json` schema | [`docs/spec/wire/xchonnect.schema.json`](../spec/wire/xchonnect.schema.json) |
| Test vectors | [`docs/spec/vectors/`](../spec/vectors/) |
| Relay conformance suite | `cargo run -p xchonnect-conformance -- relay <url>` |
